## 1. Общая команда и evidence policy

PowerShell в корне проекта:

```powershell
$env:UV_CACHE_DIR = Join-Path (Get-Location) 'artifacts/uv_cache'
uv lock --check --offline
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pytest -q --basetemp=artifacts/pytest_tmp
```

В audit использован доступный `.venv\Scripts\python.exe -m pytest ...`; initial system Temp failure и успешный повтор записаны отдельно в PROJECT_AUDIT. Для независимой воспроизводимости нужны clean clone+locked sync, а не только повтор в готовой .venv. Сохранять version/commit/command/exit и краткий test summary, не patient rows или tokens. Не добавлять mirror tests для одного лишь увеличения количества: каждый новый case проверяет failure mode контракта.

## 3. Fixture policy

Fixtures маленькие, синтетические и проверяемые вручную. Использовать pytest tmp_path под workspace basename для result files. Не commit sampled clinical rows даже для tests; создать синтетические повторные patient IDs и timestamps. Из source metadata допустимы sanitized cards/known schema names. Real network integration opt-in требует local cache и pinned source; отказ сети не превращать в unit-test regression. Synthetic «full» fixture допустим только как test artifact с test namespace, не научный результат.

Обязательные corner cases привязаны явно: numeric/category/missing/unknown/constant/all-empty→T02/T03; rare classes/invalid distributions→T01/T04/T12; conflicting labels→T02; excessive OHE dimensions→T03; deterministic seeds→T04/T10; failed trials→T04/T05; invalid JSON→T05/T06; duplicate meta rows→T06; train/test leakage→T03/T04/T07/T12. Семантический target leakage, cohort reuse, ошибочная дата prediction не ловятся одним техническим тестом — T09 review необходим.

## 4. Gates и Definition of Done

| Gate | Когда | Требуемые доказательства | Блокирует |
|---|---|---|---|
| G0 Scope | PH0 | Frozen scope/unknown official requirements, D011–D020 dispositions, source categories | Final outcome-based design changes |
| G1 Engineering | До первого full | T01–T08 на соответствующем current scope, real smoke5, no unresolved P0, strict admission/clinical fence | Full production |
| G2 Resource/protocol | После representative full | actual360+6 units, identity/provenance, measured timing/RSS, canonical schema, full validation | Expanded full batch |
| G3 Meta-data | PH8 | prospective source list/exclusions, compatible complete runs, one row/source, family groups, allowlisted predictors | Primary evaluation |
| G4 General evaluation | PH10/13 | OOF family holdouts, fixed primary/inner-only selection, all baselines, per-dataset regret/uncertainty | Any superiority claim; primary model deployment artifact freeze |
| G5 Clinical transfer | PH12 | frozen general artifact, source/patient/time checks, no clinical fitting, actual cohort results and limitations | RQ3 empirical conclusion |
| G6 Submission | PH15 | reproducibility operator check, final artifacts ledger, source terms, report/slides/demo, RTM statuses; official checklist если получена | Заявление «полностью готов к университетской сдаче» |

Общий software DoD: correct supported inputs, explicit unsupported errors, verified serialization/inference, deterministic identities, no unresolved P0, meaningful offline tests and CI. Общий research DoD: predeclared protocol, real benchmarks, valid dataset-level held-out comparisons, negative findings allowed, independent clinical transfer attempt/results with scope limits, uncertainty and exclusions disclosed. Report DoD: every empirical claim grounded in artifact, every dataset credited, scope does not exceed evidence.

Если official requirements отсутствуют к завершению, можно подтвердить готовность **research package по принятому scope**, но не соответствие неизвестной rubric. Нельзя требовать произвольного «regret улучшен наX%» как условие pass: это проектирует победу заранее.

## 5. Будущий acceptance record

Для каждого FR/NFR/SR в REQUIREMENTS заполнить status, evidence path/hash, command/date/OS/exit, reviewer и limitation. Для каждой задачи P033-* отметить test groups/outputs/DoD. Test failure требует fix или explicit scope exclusion с impact; skip не равен pass. Source/access blocker upstream не должен ошибочно окрашивать в failed рабочий general pipeline, но обязательно входит в final report.
